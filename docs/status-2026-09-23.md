## Odczyt limitów

Dotyczy sprawy z `claude-code-get-used-limit.md`.

- **statusLine nie działa w `claude -p`.** Sprawdzone eksperymentalnie na Claude
  Code 2.1.280.
- **`claude -p /usage` działa i nic nie kosztuje:** zero tur, zero kosztu,
  zero wywołań API. Notatka zakładała, że nie działa. To jest teraz preflight
  Claude. Tekst jest parsowany ściśle, a każdy nierozpoznany format daje
  `PAUSED_LIMIT_UNKNOWN` zamiast zgadywania.
- **Codex** odczytuje limit przez App Server (`account/rateLimits/read`), także
  bez generowania. Wybierane jest okno o długości 300 minut, a nie po prostu
  `primary`.
- W trakcie tury Claude zdarzenie `rate_limit_event` ze `stream-json` daje
  dodatkową ochronę: odrzucenie limitu wstrzymuje sesję zamiast ponawiać turę.
- Odrzucony wariant: nieudokumentowany endpoint `GET /api/oauth/usage`. Daje te
  same dane, ale wymaga czytania tokenu OAuth.

Szczegóły techniczne są w [feasibility.md](feasibility.md).

## Znalezione i naprawione błędy

Pierwsze trzy wyszły dopiero przy prawdziwych CLI. Z nimi żadna prawdziwa
recenzja nie miałaby szans przejść.

1. `codex exec` odrzucał `--ask-for-approval`. To opcja globalna, więc musi stać
   przed `exec`.
2. Oba CLI odrzucały schemat JSON tury (`$schema` draft 2020-12, `uniqueItems`,
   `minLength`, brak `type`). Do CLI trafia teraz okrojona wersja
   (`schemas.provider_turn_schema`), a lokalnie nadal sprawdzany jest pełny
   schemat.
3. Prompt nie opisywał reguł protokołu, więc modele zwracały tury odrzucane przez
   walidator. Dodano sekcję reguł z numerem następnego ID problemu
   i identyfikatorami wersji.
4. Niestabilny test (`test_engine_restart_during_b_cancels_old_attempt_before_stop`)
   ujawnił błąd silnika. Awaria między zapisem stanu a wysłaniem zadania kończyła
   sesję w `ERROR/cancel_unconfirmed`. Worker zapisuje teraz trwały „nagrobek”
   dla anulowanego zadania, którego nigdy nie widział.
5. Wyczerpany limit Codeksa (`ordinaryUsageAllowed: false`) dawał „limit
   nieznany” zamiast pauzy `PAUSED_LIMIT_LOW` do znanego czasu resetu. Wyszło to
   na żywym koncie.

## Pozostałe zmiany

- Obrazy workerów instalują przypięte CLI: Claude Code 2.1.280 i Codex 0.156.1.
  Katalogi OAuth to `CLAUDE_CONFIG_DIR=/auth/claude` i `CODEX_HOME=/auth/codex`.
  Workery działają z `TZ=UTC`, mają tmpfs `/tmp` i więcej pamięci.
- Worker przekazuje do CLI tylko `HOME`, `PATH`, `TZ`, katalog OAuth
  i `DISABLE_AUTOUPDATER`, nigdy kluczy API.
- `doctor` pyta działające workery o świeży odczyt limitu, wersję CLI i konto,
  zamiast czytać zmienne środowiskowe.
- Worker ma flagę `--probe`, która wypisuje odczyt limitu, wersję CLI
  i `observed_account_fingerprint` do wpisania w konfigurację.
- `scripts/probe_capabilities.py --live` składa kontrakt GO/NO-GO z prawdziwych
  odczytów.
- Zaktualizowano README, [feasibility.md](feasibility.md),
  [operations.md](operations.md) i notatkę `claude-code-get-used-limit.md`.

## Zmiany z 2026-09-24: model i effort

- **`doctor` zgłasza nieprzypięty model.** Wartość zaczynająca się od `PIN_`
  (placeholder z `example.toml`) daje `<provider> model is not pinned: …`
  i kod wyjścia 1. Wcześniej przechodziła walidację i wychodziła dopiero przy
  pierwszej turze, gdy CLI odrzuciło nieznany model.
- **Nowe wymagane pole `effort`** w `[reviewers.claude]` i `[reviewers.codex]`.
  Wcześniej effort nie był przekazywany, więc każdy CLI brał swoje ustawienie
  domyślne. Dla `gpt-6-astra` domyślny poziom to `low`.
  - Claude: `--effort`. Config przyjmuje tylko `low | medium | high | xhigh | max`.
  - Codex: `-c model_reasoning_effort="…"`, bo `codex exec` nie ma osobnej flagi.
    Dozwolone wartości zależą od modelu, więc config sprawdza tylko, czy to same
    małe litery. Literówka wyjdzie dopiero przy pierwszej turze.
  - Pole należy do niezmiennej sekcji `reviewers`: sesji rozpoczętych bez
    `effort` nie da się wznowić.
- **Skąd brać nazwy modeli.** Nazwa widoczna w `/model` to nazwa wyświetlana, nie
  identyfikator.
  - Claude: pełny identyfikator, np. `claude-opus-5-5`. Nie używać aliasu
    (`opus`, `sonnet`), bo po nowym wydaniu wskazuje inny model.
  - Codex: pole `slug` z `codex debug models`; dozwolone poziomy effortu są
    w `supported_reasoning_levels`. Katalog zależy od wersji CLI i konta, więc
    sprawdzać go w kontenerze.
- Flagi sprawdzono tylko w `--help` lokalnych CLI (Claude 2.1.281, Codex
  0.155.1), a nie w wersjach przypiętych w kontenerach. Test na żywo z 23.09
  działał bez jawnego effortu.

## Do zrobienia

1. **Wyłączyć extra usage na koncie Claude.** 23.09 było włączone: limit
   2000 EUR/mies., wykorzystane 502 EUR. Bez tego recenzje po przekroczeniu
   limitu abonamentu mogą zacząć zużywać płatne kredyty. Konto Codex miało
   `credits.hasCredits: false`.
2. **Zalogować oba CLI w ich kontenerach** (jednorazowo, interaktywnie):
   ```bash
   docker compose build
   docker compose run --rm --entrypoint claude claude auth login --claudeai
   docker compose run --rm --entrypoint codex codex login --device-auth
   ```
   Nie kopiować poświadczeń z hosta: oba systemy rotują refresh tokeny, więc dwie
   kopie jednego logowania unieważniają się nawzajem.
3. **Uzupełnić `config/reviewer.toml`:**
   ```bash
   cp config/example.toml config/reviewer.toml
   docker compose run --rm claude --probe
   docker compose run --rm codex --probe
   ```
   Wartości `observed_account_fingerprint` wpisać jako `account_fingerprint`.
   Zamiast `PIN_AFTER_LIVE_PREFLIGHT` wpisać modele; w teście zadziałały
   `claude-sonnet-5` i `gpt-6-astra`. Ustawić `effort` dla obu recenzentów
   i sprawdzić, czy wybrany poziom jest w `supported_reasoning_levels` modelu
   Codeksa (`codex debug models` w kontenerze).
4. **Sprawdzić wdrożenie w kontenerach:**
   ```bash
   docker compose up -d
   docker compose exec -T engine peer-reviewer doctor --config /config/reviewer.toml --sessions /sessions
   python scripts/probe_capabilities.py --live --output capability.json
   PEER_REVIEWER_CAPABILITY_RESULT=capability.json uv run pytest -m live tests/integration/test_capabilities.py
   ```
5. **Powtórzyć pełną sesję w kontenerach.** Na hoście przeszła; w kontenerach
   jeszcze nie była uruchamiana, bo wymaga logowania z punktu 2.
6. **Zaobserwować `/usage` w bezczynnym oknie**, gdy nie ma aktywnego okna 5h.
   Parser traktuje `Current session: 0% used` bez czasu resetu jako świeże okno,
   ale tego formatu nie widziano jeszcze na żywo. Jeśli będzie inny, parser da
   bezpieczne `unknown`, co jednak zablokuje sesję do czasu pierwszego użycia
   konta.
7. **Docker na tej maszynie:** Docker Desktop przestał działać w trakcie
   budowania. Obrazy zbudowano na natywnym silniku (`DOCKER_CONTEXT=default`).
   Albo używać tego kontekstu, albo uruchomić ponownie Docker Desktop
   i przebudować obrazy.
8. **Zacommitować zmiany.** Nic nie zostało jeszcze zacommitowane: zmiany dotyczą
   24 plików, a nowych plików jest 5, nie licząc tego.
9. Przy każdej zmianie wersji CLI powtórzyć test na żywo (feasibility.md), bo
   format `/usage`, flagi CLI i wymagania schematów mogą się zmienić.
